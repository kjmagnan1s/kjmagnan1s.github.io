Upgrade your Jev calls to 1.14, with images and long context on

Here's the prompt from my video, the two settings it turns on, and what I learned testing them. Jev is TypeSafe's AI model that only makes calls, like yes or no, or which one of these.

By Kevin Magnan · @vibewithkevin

1. The prompt

Open Claude Code in your project folder and paste this in. It tests one call on both versions before it switches anything.

Paste into Claude Code
Find every place in this project that calls TypeSafe's Jev API. Before you change anything, pick one call and run it with the same input on jev-1.13.0 and on jev-1.14.0, and show me anything that changed. If my code compares Jev's numbers to a cutoff, also run my test cases on both versions and show me what moved. Then switch every call to the model jev-1.14.0, and ask me before you change any cutoff. Send TypeSafe-Danger-Zone-Images: true only on requests that include an image or a Box question, and TypeSafe-Danger-Zone-Long-Context: true only on requests that can go over 64,000 tokens.

Swap in your own project. If you don't use Claude Code, the same steps work by hand.

2. The two settings

TypeSafe calls these "danger zone" settings. Your app sends them as headers, only on the requests that need them.

TypeSafe-Danger-Zone-Images: true

Lets you put a photo anywhere you'd put text in a Jev question. It also turns on Box, a new question type in 1.14: you name something, and Jev draws a box around where it is in the picture.

TypeSafe-Danger-Zone-Long-Context: true

Raises the limit from about 64,000 tokens per request to 262,000, at the same price. TypeSafe's docs say it's slower and less accurate.

TypeSafe's own warning"we think there is still way too much jaggedness for us to vouch for these for production use cases." Build prototypes with them first. On my normal requests, turning both on changed nothing: same answers, same speed.

3. What I learned testing it

  1. Shrink photos first. Each side has to be between 256 and 1,568 pixels, and Jev doesn't resize for you. One bad image fails the whole request. My first try with TypeSafe's chart failed until I shrank it.
  2. On long text, give it options. I hid one sentence about a spare ladder key in about 75,000 tokens of my notes, then asked two ways:
    98%Multiple choice: "where is the key kept?" It picked the bucket.
    26%Yes or no: "does it say where the key is?"
    That's one test, not a law. In shorter text the same yes-or-no question did better.
  3. Box always returns a box, even when the thing isn't in the picture. In the same request, ask yes or no whether it's there, and ignore the box when that answer is low.

4. Test one call first

TypeSafe calls 1.14 "small, subtle improvements to everything" and says most things should be a tiny bit better. The tool that grades my TikTok scripts noticed. On 1.14 it still caught every bad example, and it also flagged two of my best scripts. My cutoffs were tuned to the old version.

If your app compares Jev's numbers to a cutoff, run your test cases on both versions before you switch. The prompt above does that for you.
